# Mobile Responsiveness Audit
**Components:** HeroSection, NicheGrid, BookingForm  
**Date:** 2026-08-31  
**Scope:** Tailwind responsive prefixes, hardcoded pixels, flex/grid usage

---

## Executive Summary
**Overall Responsiveness Rating: 6.5/10**

The codebase demonstrates a **mixed approach** to responsive design:
- ✅ **HeroSection** uses responsive CSS-in-JS + Tailwind classes (good intent, but inconsistently applied)
- ✅ **NicheGrid** is well-structured with Tailwind grid (auto-fit, minmax patterns)
- ⚠️ **BookingForm** relies heavily on Tailwind classes but lacks explicit mobile-first breakpoint usage
- ❌ **Critical Issue:** Extensive use of inline pixel values in HeroSection instead of Tailwind breakpoint utilities

---

## Component-by-Component Analysis

### 1. HeroSection.tsx — Rating: 5/10
**Issues:** Heavy reliance on CSS-in-JS with inline pixel values; minimal Tailwind responsive prefixes

#### Positives:
- ✅ **Responsive grid layout**: Uses `isDesktop` state to switch between 2-column (desktop) and 1-column (mobile)
- ✅ **Flexible spacing**: Conditional padding/gaps based on `isMobile` / `isDesktop` state
- ✅ **Clamp functions**: H1 uses `clamp(2.6rem, 5.6vw, 4.25rem)` for fluid typography
- ✅ **Aspect ratio scaling**: Image plate adjusts `aspectRatio` between desktop (4/5) and mobile (4/3.4)

#### Problems:
- ❌ **No Tailwind breakpoints used** — All responsive logic is JavaScript state-based
- ❌ **Hardcoded pixel calculations** throughout:
  - `marginBottom: isMobile ? '1.5rem' : '2rem'` (should use `mb-6 md:mb-8`)
  - `fontSize: '0.8125rem'` (non-standard, no rem scale)
  - Padding: `'0.4375rem 0.9375rem 0.4375rem 0.75rem'` (micro-managed, hard to scale)
  - `left: isDesktop ? '-1.25rem' : '50%'` (floating element positioning)
- ❌ **Inconsistent typography scale** — Uses bare pixel values instead of Tailwind text-size classes
  - `fontSize: 'clamp(1.125rem, 1.6vw, 1.25rem)'` (clamp is good but mixing approaches)
  - `fontSize: '0.8125rem'`, `'0.875rem'`, `'1.0625rem'` — custom values, not leveraging Tailwind
- ⚠️ **No media query classes** — All layout shifts happen via JS state
- ⚠️ **Complex inline styles** — ~880 lines of single-file component with nested style objects

#### Responsive Prefix Audit:
- **sm:** — 0 uses
- **md:** — 0 uses
- **lg:** — 0 uses (state-based `isDesktop` at 1024px replaces it)
- **Flex/Grid:** ✅ Used (`display: 'grid'`, `flexDirection` conditional)

### 2. NicheGrid.tsx — Rating: 8/10
**Best-in-class responsive design among the three**

#### Positives:
- ✅ **Tailwind Grid with auto-fit**: 
  ```tsx
  gridTemplateColumns: 'repeat(auto-fit, minmax(min(280px, 100%), 1fr))'
  ```
  - Mobile-first: starts at 280px, fills available width
  - Automatically collapses to 1 column on small screens
  - No hardcoded breakpoints needed
- ✅ **Flexible spacing**: Uses `layout.gapCard` constant (design system integration)
- ✅ **Semantic HTML**: Links wrap cards, proper focus management
- ✅ **No hardcoded pixels** in responsive contexts
- ✅ **Flexbox for internal layout**: `display: 'flex'`, `flex: 1`, `flexDirection: 'column'`

#### Weaknesses:
- ⚠️ **Minimal Tailwind classes** — All layout via inline styles
- ❌ **No explicit sm:/md:/lg: prefixes** (but not needed due to `auto-fit` pattern)
- ⚠️ **Design system not fully leveraged** — `layout.gapCard` is good, but typography sizes are bare numbers
  - `fontSize: '3.5rem'` (emoji) — should be a defined size in theme
  - `fontSize: '1.25rem'` (h3) — should be `text-lg` or custom size utility

#### Responsive Prefix Audit:
- **sm:** — 0 uses
- **md:** — 0 uses
- **lg:** — 0 uses
- **Flex/Grid:** ✅ Excellent (`grid`, `auto-fit`, `minmax`, `flex`)

### 3. BookingForm.tsx — Rating: 7/10
**Good Tailwind adoption, but mixed with inline styles**

#### Positives:
- ✅ **Tailwind classes with responsive prefixes**:
  ```jsx
  className="hidden sm:block w-8 h-1 bg-warm-gray-200"  // ✅ sm: prefix
  className="w-10 h-10 rounded-full flex items-center justify-center"
  className="w-4 h-4 cursor-pointer"  // ✅ form controls scale
  className="sm:w-5 sm:h-5 cursor-pointer"  // ✅ responsive checkbox size
  ```
- ✅ **Flex-based layout**: `flex gap-4`, `flex items-center`, `flex gap-2` throughout
- ✅ **Space utilities**: `space-y-4`, `space-y-6` for consistent vertical rhythm
- ✅ **Max-width constraint**: `max-w-2xl mx-auto` for desktop
- ✅ **No hardcoded breakpoints** — uses Tailwind's built-in breakpoints
- ✅ **Responsive form inputs**:
  - Input sizing responsive to focus state
  - Textarea with `h-32 resize-none` is fixed, but justified (form UX)
- ✅ **Animations**: `animate-fade-in-up` (custom animation, class-based)

#### Weaknesses:
- ⚠️ **Inconsistent style approach** — Mixing Tailwind classes with inline styles
  - Progress indicators use both: `className` + `style={{...}}`
  - Some margin/padding via classes, some via inline
- ❌ **Hardcoded inline pixel values in inline styles**:
  ```jsx
  style={{ minWidth: '56px', minHeight: '56px', padding: '16px' }}  // ❌ hardcoded
  ```
  Should be: `w-14 h-14 p-4` (Tailwind)
- ⚠️ **Limited breakpoint usage** — Only one `sm:` prefix found, mostly single-size layouts
- ⚠️ **Typography sizes** — Bare pixel values in Tailwind classes:
  - `text-2xl` ✅ (good, using scale)
  - But then: `fontSize: '0.95rem'` ❌ (inline override, breaks scale)

#### Responsive Prefix Audit:
- **sm:** — 2 uses (progress bar, checkbox size)
- **md:** — 0 uses
- **lg:** — 0 uses
- **Flex/Grid:** ✅ Excellent (`flex`, `gap`, `items-center`, `justify-center`, etc.)

## Key Findings

### 1. **Inconsistent Responsive Strategy**
- **HeroSection**: Abandons Tailwind breakpoints in favor of JavaScript state (`isMobile`, `isDesktop`)
- **BookingForm**: Mixes Tailwind classes and inline styles
- **NicheGrid**: Pure inline styles with CSS Grid (auto-fit pattern)

→ **Recommendation**: Unify on Tailwind-first approach with `sm:`, `md:`, `lg:` prefixes

### 2. **Typography Not Using Tailwind Scale**
- Examples: `fontSize: '0.8125rem'`, `'0.9375rem'`, `'1.0625rem'`
- Should leverage Tailwind's scale: `text-xs`, `text-sm`, `text-base`, `text-lg`, etc.
- **Gaps in scale**: Custom fractional sizes (`.8125rem` = 13px) don't align with design system

→ **Recommendation**: Extend Tailwind `fontSize` theme to include custom sizes, use classes instead of inline

### 3. **Breakpoint Misalignment**
- HeroSection uses `640px` (sm) and `1024px` (lg) via JavaScript
- Tailwind defaults: `sm: 640px`, `md: 768px`, `lg: 1024px`, `xl: 1280px`
- **BookingForm/NicheGrid**: Never reference breakpoints, static layouts

→ **Recommendation**: Use Tailwind breakpoints consistently or document why state-based approach is chosen

### 4. **Accessibility Concerns**
- Minimal testing for `prefers-reduced-motion` (HeroSection has one media query)
- Touch targets on BookingForm checkboxes need verification (`w-4 h-4` = 16px is below 44px WCAG minimum)
- Checkbox min-touch size inline style (`minWidth: '56px'`) contradicts visual size

→ **Recommendation**: Audit touch targets on mobile, implement `prefers-reduced-motion` globally

## Recommendations (Priority Order)

### 🔴 Critical (Fix First)
1. **Replace HeroSection inline pixels with Tailwind utilities**
   - Migrate `isMobile`/`isDesktop` state to `sm:`, `md:`, `lg:` classes
   - Example: `marginBottom: isMobile ? '1.5rem' : '2rem'` → `mb-6 md:mb-8`
   - Refactor into `<div className="px-4 sm:px-6 md:px-8">`

2. **Audit and fix checkbox touch targets**
   - Current: `w-4 h-4` (16px) — below WCAG 44x44 minimum
   - Fix: Wrap in larger clickable area or use `w-5 h-5 sm:w-6 sm:h-6`

### 🟡 Important (Next Sprint)
3. **Extend Tailwind `fontSize` theme**
   - Add custom sizes to `tailwind.config.ts`: `.8125rem`, `.9375rem`, `1.0625rem`
   - Convert inline `fontSize` values to Tailwind classes
   - Ensure all typography uses the extended scale

4. **Document responsive strategy**
   - Clarify: Why does HeroSection use JS state vs. Tailwind breakpoints?
   - Create component guidelines: "Always use `sm:`, `md:`, `lg:` prefixes, never inline responsive logic"

5. **Add mobile-first breakpoint tests**
   - Verify layouts at 320px, 640px, 1024px, 1280px
   - Check text reflow, image scaling, form field spacing

### 🟢 Nice-to-Have (Future Optimization)
6. **Consolidate layout constants**
   - `layout.gapCard`, `layout.gutter`, `layout.sectionYLg` are good
   - Extend for responsive spacing: `layout.gapCard.sm`, `.md`, `.lg`

7. **Create responsive component patterns**
   - Example: `ResponsiveGrid` wrapper with `auto-fit`/`minmax` built-in
   - Reduce duplication across NicheGrid-like components

## Conclusion

The codebase is **functionally responsive** but **architecturally inconsistent**. HeroSection prioritizes design control via JavaScript over Tailwind's responsive utilities, while BookingForm and NicheGrid show better alignment with Tailwind practices.

**To improve from 6.5/10 to 8/10+:**
1. Migrate HeroSection to Tailwind breakpoint classes
2. Fix touch targets on form controls
3. Extend Tailwind theme with missing typography sizes
4. Establish team guidelines: "Tailwind-first, no inline responsive logic"

**Priority: HeroSection refactor** — the most-visited component should model best practices.
